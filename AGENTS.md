# Instructions for work in this repository

Read [the current operating instructions](instructions/current-v9.1.md), [source provenance](docs/provenance.md), and [version conflicts](docs/versions-and-conflicts.md) before changing framework content.

- Ground each substantive claim in an identified artifact, observation, or explicit inference. Prior assistant output is context, not independent evidence.
- Preserve UNKNOWN, [FILL], and [DATA_VOID]. Do not invent lens functions, numeric thresholds, registry entries, G/P-code tables, source citations, deployment status, or performance results.
- Preserve source exports. Put explanations and amendments in current documents, with provenance and a version note. Do not silently rewrite a recovered source to make versions agree.
- Use the current v9.1 tag profile in current instructions. Source files retain their historical profiles. Never infer a tag's meaning from its letter alone.
- Don Sol is the framework's sign-off authority. Publishing a documentation update does not ratify every proposed source field or establish a scientific claim as true.
- Keep the Ω-Gate, independent verification, demotion, quarantine, dependency re-audit, and narrative/evidence boundary intact. Cross-model agreement is not independent verification.
- Keep the five-layer L0–L4 architecture. Do not resurrect retired layer models as current or claim a complete lens roster from a partial source.
- Preserve Arc manuscripts; create derived work only within an explicit request. Cathedral vocabulary stays out of Arc-facing prose.
- Report prepared, executed, published, served-page-verified, and playback-verified as separate states. Inspect the actual artifact or external result before claiming completion.
- Reuse completed work and fix the defective component. Do not add charges, subscriptions, schedules, destinations, infrastructure changes, or publication authority through a documentation edit.
- Do not commit credentials, private correspondence, financial details, account inventories, private receipts, personal handovers, signed URLs, or unrelated unpublished works. This repository is public.
- Run `python3 tools/validate_repository.py` after changes. Update `manifest.json`, `CHANGELOG.md`, and source hashes when applicable. The checker is document validation, not a model benchmark.
- Read `docs/capabilities-and-evolution.md` for extensions. Keep documented methods, supplied code, session availability and proposals distinct. For changes to preflight behavior, run `python3 -m unittest discover -s tools -p 'test_*.py'`. Its result does not authenticate authority, verify sources, execute jobs or resolve the open v8.1 cascade rules.

Use direct, humane prose. Keep technical terms where they improve precision. If reality contradicts the model, the model changes.
