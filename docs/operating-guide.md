# Operating guide

Load [the full boot](../instructions/current-v9.1.md), [compact boot](../instructions/current-v9.1-compact.txt), or [light boot](../instructions/light-boot.txt), then provide the actual source/state and task. Instructions organize a session; they do not install an application or make a source available without retrieval.

## Ask plainly

Ordinary language is valid. A structured job can use:

```text
Command: Analyze
Lens: Engineer / Skeptic
Evidence: Attached drawing and measurements; no external verification yet
Output: Short explanation and one next action
Task: Identify which measurements are still needed before choosing a design.
```

Common jobs include Quick, Summarize, Analyze, Compare, Plan, Create, Audit, and Meta. These are a convenient interface inherited from the earlier guides, not an assertion of a complete current command-code registry. Select a lens only when its relevant definition is known.

## Boot report

State the loaded repository/component edition, actual model/platform if known, available tools, what memory or saved state was really loaded, evidence limits, source conflicts, and the next authorized job. Do not copy the source v9.0 bundle's prewritten FULL MODE / no-conflicts report as if those checks happened in the current session.

## Work one closed loop

1. Name the intended outcome and actual starting checkpoint.
2. Separate observation, sourced claim, inference, proposal, and unknown.
3. Check feasibility, units, dimensions, resources, permissions, and failure consequences.
4. Perform the smallest useful authorized action.
5. Inspect the actual artifact or external result; compare it with acceptance criteria.
6. Save what changed, what was measured, what remains unresolved, and the next action.

If a path fails, record the failure and changed condition needed before retrying. Reuse completed assets. A failed upload does not justify rewriting a script; a broken control does not justify redesigning the page.

## Output

Lead with the answer or delivered outcome. Give the evidence and limits needed to assess it. Use structured data for ledgers and exact comparisons; use plain narrative for explanations and Arc-facing work. Avoid turning an ordinary reply into a registry dump.

In engineering, preserve explicit dimensions, units, coordinate frames, material limits, and boundary conditions across revisions. Never use a persuasive rendering as a measurement. Validate the actual deliverable against the right datum.

## Close and resume

For a job requiring explicit machine-readable prerequisites, use the [job-packet example](../examples/job-packet.json) and [local preflight/evolution guide](capabilities-and-evolution.md). Keep real job records private. The inspector checks declared records and executes no action. Record a tool's actual observed binding and limits; do not infer availability from its mention in the capability register.

Use the [handoff template](../examples/session-handoff.md). Preserve source references, actual artifact identities, changes, corrections, confirmed outcomes, held decisions, unknowns, and the next action. The next session resumes from that record and verifies changeable external state when necessary.

Keep personal and operationally sensitive state outside this public repository. A blank template carries no private session state and claims no completed work.
